# S3 - Real login session (httpOnly cookie, survives refresh)

Size: M. Why: Today credentials live only in React memory: every refresh logs the user out and the password is readable by JavaScript. This fixes it in the Next.js layer without changing the backend.

TASK S3 - httpOnly cookie session in the Next.js layer. No backend change, no new npm dependency (use Node crypto).
1. Add route handlers: POST /api/session/login (verify the credentials with GET /api/v1/account/me on the backend using Basic auth), POST /api/session/logout, GET /api/session/me.
2. On login store the credentials in an httpOnly, SameSite=Strict cookie (Secure when NODE_ENV=production), encrypted with AES-256-GCM using a key derived from env SESSION_SECRET (fail clearly if missing in production), max age 12h.
3. The existing proxy route (/api/backend/[...path]) must read the cookie and add the Authorization header server-side (keep its other behaviour). Reject state-changing requests whose Origin header does not match the app origin (CSRF).
4. Update the auth context: no password kept in React state; on load call /api/session/me to restore the session after a refresh; logout calls the logout route. Keep the public hook interface so pages do not change. 401 from the backend clears the session.
5. After registration redirect to /login with a success message.
6. Add SESSION_SECRET (placeholder) to frontend/.env.example. Run npx tsc --noEmit and npm run build.
