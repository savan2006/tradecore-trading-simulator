1. frontend/src/lib/use-api-query.ts: the .then() sets state even when the effect was already aborted (React StrictMode runs effects twice in dev, and session changes cancel requests). Ignore results of aborted runs in BOTH then and catch, and never surface an AbortError/'signal is aborted...' message as a data error. 2. frontend/src/lib/api.ts: loadDashboard (and any other loader using Promise.allSettled) converts an abort into a per-section error string that then gets displayed. If signal.aborted, throw/rethrow so the caller ignores it. Search api.ts for every allSettled and fix the same way.
